# Windsurf 悄悄变成了 Devin——我用 Cascade 写了三个月代码，然后它告诉我"你用的那个功能下个月就没了"

6月2日早上，我像往常一样打开 Windsurf，准备继续改昨天没写完的一个小工具。

界面没变。快捷键没变。连那个熟悉的 Cascade 聊天窗口都在老位置。

但标题栏上的字，变了。

**Windsurf IDE → Devin Desktop。**

我盯着那行字看了三秒，确认不是眼花。然后去官网看了一眼公告——Cognition 收购了 Windsurf，品牌合并，Cascade 7月1日停服，新引擎叫 Devin Local，用 Rust 重写了。

> 悄无声息地，你用的工具换了名字。你甚至不知道这算是升级还是告别。

---

## 一

我用 Windsurf 大概是今年3月份的事。

当时 Cursor 3 刚发，Glass 界面惹了一堆争议，我在文章里写过"第二天就后悔了"。转头就去试了 Windsurf，心想总得有个能打的备胎。

**Cascade 是真的好用。**

它不是那种"你写一行、它补一行"的传统补全。它是**流感知**的——能同时扫整个代码库，理解文件之间的关系，然后一口气改五六个文件，连终端命令都自己执行。

举个真实的例子：

我有一个 Node.js 的小项目，想加一个用户认证模块。传统的 AI 编程工具，你得告诉它"先建 auth 文件夹，再写 middleware，再写路由，再写数据库 schema"——每一步都要你说。

Cascade 呢？我说了句"加个 JWT 认证，用户表用 PostgreSQL"，它自己：

- 建了 `src/auth/` 目录
- 写了 middleware、router、service 三层
- 改了 `package.json` 加了 `jsonwebtoken` 和 `pg`
- 甚至帮我跑了一遍 `npm install`
- 最后在终端里显示了一个绿色的 ✅

整个过程不到两分钟。我连文件夹都没新建。

**这是真的在写代码，不是真的在帮你写代码——这两件事的差别，用过的人都知道。**

---

## 二

但 Cascade 也有问题。最大的问题是**它太自信了**。

它会自己决定改哪些文件，有时候改错了你也看不出来。有几次它改了我一个工具函数，表面上看代码跑通了，但边缘场景全崩了。

我写过一篇"AI 写的代码跑通了，我却不敢动"，说的就是这种感受——**AI 生成的代码像一个你不完全信任的同事，活儿干得漂亮，但你不敢把关键模块交给它。**

更麻烦的是，Cascade 的上下文窗口不是无限的。项目一大，它就开始"忘记"前面的设定。你让它按照某个模式写代码，写到第 15 个文件的时候，它已经忘了你一开始说的那个模式是什么了。

这些问题，我在用了三个月之后才逐渐摸清。摸清之后，就学会了怎么跟它"说话"——用更具体的指令，更小的任务拆分，更多的中间检查。

**就像跟一个聪明但急躁的实习生合作：你得学会怎么给他布置任务。**

---

## 三

然后6月2日，它变成了 Devin Desktop。

我第一时间打开看了看变化：

- **Devin Local** 代替 Cascade 成了默认引擎——Rust 重写，理论上更快
- **Agent Command Center**——一个新的面板，可以管理多个本地和云端的 agent
- **ACP（Agent Client Protocol）**——一个开放协议，理论上其他工具也能接入
- Cascade 变成了"legacy option"，7月1日彻底停服
- 所有老用户的套餐和设置原封不动迁移过来
- Devin Review 免费包含在所有套餐里

表面上看，升级了。

但打开 Devin Local 试了一下，**第一感觉是：它没有 Cascade 那么"聪明"了。**

不是慢，是笨。同样的任务，Cascade 一次性搞定的，Devin Local 需要我多解释两遍。它好像失去了 Cascade 那种"我理解你要什么"的直觉。

当然，这可能只是我刚切换过来还没适应。但直觉告诉我，**Rust 重写的不只是性能，还有一些说不清的东西也一起重写了。**

---

## 四

这件事给我最大的感受是什么？

**你用得再顺手的工具，也可能一夜之间变成别的东西。**

Windsurf 被 Cognition（Devin 的母公司）收购，这在商业上是完全合理的。Devin 之前是纯云端的 agent，现在想做一个"IDE + agent 管理器"的全能产品，Windsurf 的 Cascade 技术正好填补了这个空缺。

但从用户的角度，这就是一个你信任的工具，突然换了主人、换了名字、换了引擎，然后告诉你"你习惯的那个功能下个月就没了，用新的吧"。

> 你不是用户，你是测试员。你在帮他们验证新引擎好不好用，而他们甚至没有提前通知你。

这让我想起了之前写"卸载 Cursor 第7天"的时候，也是类似的感受——**工具生态变化太快了，快到你的工作流还没稳定，就已经过时了。**

---

## 五

那现在怎么办？

我的建议是：**别慌，但也别盲目乐观。**

1. **7月1日之前，Cascade 还能用**——如果你现在的项目正关键，别急着切换。等7月之后再决定。

2. **Devin Local 需要时间磨合**——新引擎肯定有 bug，有性能问题，有学习曲线。给它一个月，也给你自己一个月。

3. **备胎还是要有的**——这件事再次证明，AI 编程工具不能只靠一个。我的主力现在是 Claude Code + Trae，Windsurf/Devin 当辅助。三个工具互相补位，谁也替代不了谁。

4. **别把工作流绑死在一个工具上**——用标准化的 prompt 模板、项目结构约定、代码审查流程。这样即使工具变了，你的方法论还在。

---

## 六

最后说句实在话。

Cascade 停服这件事，表面上看是一个工具的告别。但往深了想，它反映的是整个 AI 编程工具行业的一个趋势：**从"辅助编程"到"自主编程"的转变。**

Cascade 是一个很好的辅助工具——它帮你写代码，但你来主导。

Devin 想做的，是**你来管理 agent，agent 来写代码**。这是两种完全不同的工作模式。

我不知道 Devin Local 能不能做到它承诺的那么好用。但我知道一件事：

**当你的工具从"帮你干活"变成"替你做主"的时候，你得想清楚——你到底是要一个助手，还是一个老板？**

我选助手。
